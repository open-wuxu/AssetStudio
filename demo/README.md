# AssetStudio · 智慧工厂数字孪生大屏

基于 [`docs/prd.md`](../docs/prd.md) 的「虚拟工厂 A / 车间 A / 产线 01」场景，使用 **Three.js r186** 构建的可交互数字孪生演示。包含一个可直接运行的网页与一段 **2K / 60fps / 30 秒** 的演示视频。

> 所有遥测、产量、告警与设备状态均为**模拟数据**，仅用于产品概念与交互演示，不代表真实生产数据。

## 运行网页

```bash
cd demo
npm install          # 安装 three / puppeteer-core（录制用）
npm run dev          # http://127.0.0.1:4173
```

网页使用 ES Module + importmap，**必须通过 HTTP 服务打开**，不能直接双击 `index.html`（`file://` 会被浏览器拦截模块加载）。

### 交互

| 操作 | 效果 |
| --- | --- |
| 拖拽 | 旋转视角，自动进入手动模式 |
| 滚轮 | 缩放 |
| 点击设备 / 左侧资产树 | 选中设备，出现轮廓线框、包围框、地面光环与取景框；右侧切换设备卡与业务页；镜头平滑聚焦 |
| 顶部页签「总览 / 生产 / 运维 / 检测 / 物流」 | 切换业务页面，并跳到该场景的代表时刻（如检测页会停在扫描中） |
| 自动演示 / 继续演示 | 播放或暂停 30 秒完整时间线 |
| 重置视角 | 回到开场全景并从头播放 |
| 底部时间轴 | 点击任意位置跳转 |
| `Space` / `R` / `Esc` | 播放暂停 / 重置 / 取消选中 |

镜头关注或选中设备时，以下三处同步变化：

1. 三维设备：呼吸式线框、包围框、地面光环、屏幕取景框；
2. 右侧设备卡：名称、状态、三项实时指标；
3. 业务面板：切换到该设备对应的生产 / 运维 / 检测 / 物流页面。

## 视频规格（实际导出）

以最终 `ffprobe` 结果为准（录制脚本会在终端打印）：

| 项目 | 值 |
| --- | --- |
| 分辨率 | **2560 × 1440（2K / QHD）** |
| 帧率 | **60 fps** |
| 时长 | 30.0 s / 1800 帧 |
| 编码 | H.264 High Profile，Level 5.1，`yuv420p` |
| 码率 | 约 27.3 Mbps（CRF 16） |
| 文件大小 | 约 98 MB |
| 音轨 | 无 |
| 容器 | MP4，`+faststart` |

按需求将原本的 4K 目标调整为 **2K**。网页内部仍以 2560×1440 原生渲染（DPR=1、2×MSAA、半分辨率 Bloom），并非低分辨率放大。

### 重新录制

```bash
cd demo
npm run record                 # 30s 全片，本机约 11 分钟
FRAMES=180 OUT=test.mp4 npm run record   # 3 秒试录
```

录制链路：无头 Chrome（ANGLE Metal）→ 确定性时间线逐帧渲染 → JPEG 95 帧序列 → ffmpeg libx264 CRF 16。帧率固定 60fps，时间由 `t = frameIndex / 60` 驱动，因此不含实时渲染抖动。

依赖：本机 Chrome（默认 `/Applications/Google Chrome.app`，可用 `CHROME_PATH` 指定）、`ffmpeg` / `ffprobe` 在 PATH 中。

## 场景与推断结构

### 参考图说明

本次任务**未附带参考图**，因此无法逐项比对参考图的布局比例与配色。视觉方向依据提示词推断：

- 深色工业空间 + **荧光黄绿色**强调色（`#C8FF3D`）；
- 低照度厂房、金属 PBR 材质、半透明防护板、细密设备细节；
- 大屏式信息架构：左侧资产树、中央三维场景、右侧业务面板、底部时间线。

如提供参考图，可进一步对齐：建筑比例、摄像机焦段、面板分割比例、字体与强调色色相。

### 重建与补全

- **厂房**：约 68 × 36 × 9.5 m 的车间，后墙、结构柱、屋面桁架、洗墙灯、吊灯、桥架、压缩空气主管；
- **产线**：进料 / 出料辊道输送线、取放工位、安全围栏、光幕、机器人控制柜；
- **机械臂**：6 轴层级骨架，比例按 3.75 m 工作半径推断；包含底座、回转、肩/肘/腕、平行夹爪、气管、线缆、伺服与铭牌；
- **在线检测**：门架、9 点传感器阵列、激光扫描面、点云、控制柜与状态灯；
- **AGV**：四轮底盘、辊道台面、托盘与料箱、激光雷达、避障、充电触点、状态灯；
- **加工与动力设备**：4 台数控加工中心、螺杆空压机 + 储气罐、配电柜、货架、托盘、缓存工件；
- **工业细节**：螺栓、软管、线缆、桥架、安全条纹、地面导向线、工位标识、墙面大字。

不可见部分按行业常识补全：机械臂关节的伺服/减速机关系、夹爪与工件的抓取位置、输送线滚筒与侧向导轨、检测门架与输送线的空间关系、AGV 与工位的接驳位置。

### 模型来源

**全部模型由 Three.js 程序化几何实时构建，未使用外部 GLB / glTF / 贴图资源。**

原因：

1. 任务未提供参考图或指定模型，外部模型难以保证与场景比例、关节关系和动画时序一致；
2. 需要离线可复现、可逐帧确定性渲染；
3. 避免第三方模型的许可与下载依赖问题。

提示词建议复杂设备优先使用 GLB。本场景以「运动关系可控、细节可程序化扩展」为优先：机械臂关节、夹爪、输送线、检测门架、AGV、CNC 均为参数化构建，便于后续替换为真实 GLB 而不改变时间线与数据绑定逻辑。

程序化贴图（设备屏幕、铭牌、警示条纹、地面标识）均由 Canvas 生成。字体使用 macOS 系统字体（PingFang SC / SF Pro / DIN Alternate），无外部字体文件。

依赖：Three.js r186（MIT）。`vendor/three/` 为运行所需的 three 构建与 addons。

## 技术实现

| 模块 | 方案 |
| --- | --- |
| 三维 | Three.js r186，WebGL2，PBR + ACES Filmic |
| 后期 | EffectComposer + RenderPass + UnrealBloomPass（半分辨率）+ OutputPass；2×MSAA |
| 场景 | 程序化几何、InstancedMesh 滚筒、CanvasTexture 屏幕/铭牌/地面标识 |
| 灯光 | 1 主平行光（2048 阴影）+ 补光 + 半球光 + 局部点光；顶棚结构不投影，避免大面积阴影压暗 |
| 相机 | 21 个关键帧的 Catmull-Rom 位置/注视点 + FOV 插值；AGV 段动态跟随并与关键帧混合 |
| 交互 | OrbitControls + Raycaster 拾取 + 相机 Tween + 选中高亮 |
| 标签 | DOM 标签逐帧投影；Raycaster 遮挡检测；不遮挡时淡入 |
| UI | 原生 ES Module + SVG/CSS 图表，无前端框架；`rem` 随视口缩放 |
| 数据 | 单一 `timeline.js` 确定性状态（机器人 / 检测 / AGV / 镜头 / 页面 / 选中） |

### 确定性录制

`?capture=1` 模式下：

- 不启动 `requestAnimationFrame` 主循环，由 `window.__renderAt(t)` 单帧驱动；
- 所有运动、光照、扫描、粒子、轮速、镜头都是 `t` 的函数；
- 关闭 CSS 动画/过渡，片尾透明度由 `t` 计算；
- 标签 / 面板强制每帧刷新；
- 以 2560×1440、DPR=1 截图，避免画布尺寸变化。

### 性能

本机（Chrome 156，ANGLE Metal，AMD Radeon Pro 5300M）实测：

- 2K 单帧渲染约 **45–80 ms**；
- JPEG 95 截图约 **230–260 ms**；
- 1800 帧合计约 **10.8 分钟**（含 ffmpeg 编码，本机实测）。

交互模式按设备像素比最高 1.5 渲染；如帧率不足可降低 DPR。

## 已知限制

- 演示数据为前端模拟，未接入真实 MQTT / HTTP / 时序数据库；PRD 中的设备接入与真实数据链路不在本次视觉 Demo 范围内。
- 视频无音轨；未加入背景音乐或旁白。
- 全部设备为程序化近似模型，不等同于厂商 CAD；如接入真实 GLB，需要重新校准关节轴心、夹爪抓取点和碰撞体。
- 参考图缺失，配色与布局为推断；提供参考图后可做一轮视觉对齐。
- 网页固定 16:9 大屏布局，小屏设备会等比缩小，不提供移动端重排。
- 2K 60fps 依赖 GPU；低性能设备打开网页时可能需要降低 DPR。
